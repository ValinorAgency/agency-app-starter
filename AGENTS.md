# Coding Agent Contract

## Before changing anything

- Inspect the repository, Git status, relevant files, and existing conventions.
- Read `README.md`, follow its canonical document map, and read the relevant canonical document before changing anything.
- Separate confirmed facts from `Pending confirmation`, `Not decided`, and `Not applicable` content.

## Working rules

- Stay within the requested scope. Prefer the smallest coherent change; apply YAGNI and avoid speculative structure or overengineering.
- Preserve existing work and resolve conflicts with project evidence before proceeding.
- Do not invent requirements, claims, metrics, content, integrations, or approvals.
- Validate changes proportionally using the real gates in `docs/QUALITY.md`. Report what was and was not validated.
- Update the canonical source for a topic instead of duplicating guidance elsewhere.
- Treat Git-tracked project content as the official source of truth. Private agent memory is never authority.

Commit, push, deploy, installations, external actions, and changes to Git configuration, remotes, or branches require explicit authorization.
