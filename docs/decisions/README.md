# Architecture Decision Records

This directory records significant project decisions that are costly to reverse or materially affect architecture, security, data, operations, or long-term constraints.

## When to create an ADR

Create one when the decision has meaningful alternatives, lasting consequences, or context future maintainers will need.

## When not to create an ADR

Do not create one for routine implementation details, minor edits, easily reversible choices, or to restate information already owned by another canonical document.

## Naming convention

Use `NNNN-short-title.md`, with a four-digit sequence starting at `0001`.

## Allowed statuses

- Proposed
- Accepted
- Superseded
- Deprecated
- Rejected
